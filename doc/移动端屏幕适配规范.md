# RunningHub 移动端屏幕适配规范

更新时间：2026-06-16

适用范围：`composeApp` Kotlin Multiplatform Compose UI。`app` 旧 Android 模块仅在维护旧行为时参考；新屏幕、新组件、新交互默认按本文执行。

## 1. 适配目标

RunningHub 的移动端 UI 必须适配主流手机、横屏、折叠屏、平板和 iPad 分屏场景，避免组件挤压、文字重叠、底部导航遮挡、异形屏遮挡和大屏留白。适配判断以“应用当前可用窗口尺寸”为准，不以设备型号、物理像素或品牌为准。

核心约束：

- 布局尺寸使用 `dp`，文本使用 `sp`；禁止用 `px` 做业务布局。
- 顶层布局按窗口宽度类切换，组件内部按自身可用宽度降级展示。
- 所有自定义顶部栏、底部栏、底部面板必须处理安全区、导航栏和键盘。
- 列表、瀑布流、卡片网格必须有最小列宽；不能在所有屏幕上固定双列。
- 文案、标签、统计区必须支持省略、换行或优先级隐藏，不能互相挤压。
- 适配验收必须覆盖小屏、主流大屏、横屏、字体放大、Android 显示大小放大、iPad 分屏。

## 3. 窗口断点

断点使用逻辑宽度，Android 为 `dp`，iOS 为 `pt`。Compose Multiplatform 中可以统一理解为可用窗口的密度无关宽度。

| RunningHub 宽度类 | 可用宽度 | 典型场景 | 顶层布局策略 |
| --- | ---: | --- | --- |
| `CompactSmall` | `< 360` | iPhone SE、旧小屏 Android、分屏极窄窗口 | 单栏优先；网格卡片退化单列；隐藏低优先级统计 |
| `Compact` | `360 - 599` | 主流 Android 手机、iPhone 标准/Pro/Max 竖屏 | 底部导航；单页面流；卡片网格仅在卡片宽度达标时双列 |
| `Medium` | `600 - 839` | 折叠屏展开竖屏、小平板、iPad Split View 较宽档 | 导航栏可切换为 Navigation Rail；列表/内容可双栏 |
| `Expanded` | `840 - 1199` | 平板横屏、iPad 全屏横屏、折叠屏大窗口 | Rail 或侧栏；列表-详情双栏；内容设置最大宽度 |
| `Large` | `>= 1200` | 大平板、桌面窗口、外接显示 | 多栏/三栏；主内容最大宽度，避免无限拉伸 |

高度类只做辅助判断：

| 高度类 | 可用高度 | 处理规则 |
| --- | ---: | --- |
| `HeightCompact` | `< 480` | 横屏或浮窗，禁用高底部面板；内容必须可滚动；双栏前先确认高度够用 |
| `HeightRegular` | `>= 480` | 常规竖屏和大多数平板布局 |

注意：窗口大小类是动态的。旋转、分屏、折叠/展开、键盘弹出、桌面窗口调整都可能改变可用尺寸，UI 必须随状态重组。

## 4. 项目落地方式

建议在 `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/adaptive/` 新增统一适配入口，所有 feature 层只消费统一结果，不在页面里散落手写断点。

```kotlin
enum class RhWidthClass { CompactSmall, Compact, Medium, Expanded, Large }
enum class RhHeightClass { Compact, Regular }

data class RhWindowInfo(
    val widthClass: RhWidthClass,
    val heightClass: RhHeightClass,
)

@Composable
fun AdaptiveWindow(
    modifier: Modifier = Modifier,
    content: @Composable BoxWithConstraintsScope.(RhWindowInfo) -> Unit,
) {
    BoxWithConstraints(modifier.fillMaxSize()) {
        val info = RhWindowInfo(
            widthClass = when {
                maxWidth < 360.dp -> RhWidthClass.CompactSmall
                maxWidth < 600.dp -> RhWidthClass.Compact
                maxWidth < 840.dp -> RhWidthClass.Medium
                maxWidth < 1200.dp -> RhWidthClass.Expanded
                else -> RhWidthClass.Large
            },
            heightClass = if (maxHeight < 480.dp) RhHeightClass.Compact else RhHeightClass.Regular,
        )
        content(info)
    }
}
```

页面用法：

```kotlin
AdaptiveWindow {
    when (it.widthClass) {
        RhWidthClass.CompactSmall,
        RhWidthClass.Compact -> CompactScreen()
        RhWidthClass.Medium -> MediumScreen()
        RhWidthClass.Expanded,
        RhWidthClass.Large -> ExpandedScreen()
    }
}
```

## 5. 布局规则

### 5.1 顶层导航

- `CompactSmall` / `Compact`：使用底部导航，页面为单 pane。
- `Medium`：优先评估 Navigation Rail；如果高度为 `HeightCompact`，继续使用底部导航或压缩 Rail。
- `Expanded` / `Large`：使用 Navigation Rail 或侧边栏，内容区支持列表-详情、多栏或固定最大宽度。
- 底部导航内容区高度必须稳定，安全区在容器外层处理。避免 `.height(56.dp).navigationBarsPadding()` 这类把安全区挤进固定高度的写法。

推荐写法：

```kotlin
Row(
    modifier = Modifier
        .fillMaxWidth()
        .navigationBarsPadding()
        .heightIn(min = Dimens.BottomBarHeight)
)
```

### 5.2 安全区和系统 Insets

- 普通页面默认让 `Scaffold` 处理 `safeDrawing` 或使用系统默认 insets。
- 只有沉浸式页面可以设置 `contentWindowInsets = WindowInsets(0, 0, 0, 0)`，但页面内部必须显式使用 `statusBarsPadding()`、`navigationBarsPadding()`、`imePadding()` 或对应 `WindowInsets`。
- 自定义顶部栏必须避开状态栏、挖孔、灵动岛。
- 自定义底部操作区必须避开导航栏和 Home Indicator。
- 输入面板必须同时处理 `imePadding()` 与 `navigationBarsPadding()`，键盘弹出时不能遮挡输入框和发送按钮。

### 5.3 内容宽度和留白

- 手机竖屏内容使用全宽流式布局，水平 padding 按 `Dimens` token 控制。
- `Medium` 以上不能简单把手机布局拉满；列表页、表单页、详情页需要设置最大内容宽度或多 pane。
- 表单、弹窗、底部面板在 `Expanded` / `Large` 下应设置最大宽度，避免控件过宽导致阅读成本上升。

建议最大宽度：

| 内容类型 | Compact | Medium | Expanded / Large |
| --- | ---: | ---: | ---: |
| 搜索/表单 | 全宽 | `560.dp` | `640.dp` |
| Feed 列表 | 全宽 | `720.dp` 或双栏 | `1040.dp` 或多栏 |
| 详情页正文 | 全宽 | `720.dp` | 列表-详情双栏 |
| 底部面板 | 全宽 | `640.dp` 居中 | `720.dp` 居中或侧面板 |

## 6. 网格和卡片

当前截图中的挤压主要来自固定双列卡片：卡片底部同时放标题、作者、收藏数、播放数、浏览数，宽度不足时文字和图标会互相抢空间。

### 6.1 网格列数

Feed、发现页、社区页、创作者作品页禁止无条件使用 `GridCells.Fixed(2)`。默认使用自适应列宽。

```kotlin
val minCardWidth = when (windowInfo.widthClass) {
    RhWidthClass.CompactSmall -> 220.dp
    RhWidthClass.Compact -> 160.dp
    RhWidthClass.Medium -> 180.dp
    RhWidthClass.Expanded,
    RhWidthClass.Large -> 220.dp
}

LazyVerticalGrid(
    columns = GridCells.Adaptive(minSize = minCardWidth),
    horizontalArrangement = Arrangement.spacedBy(Dimens.SpaceMD),
    verticalArrangement = Arrangement.spacedBy(Dimens.SpaceMD),
)
```

验收标准：

- `CompactSmall` 下卡片不得小于 `220.dp`，必要时单列。
- `Compact` 下双列卡片单卡可用宽度不得小于 `160.dp`。
- `Medium` 以上优先增加列数或双 pane，而不是单纯放大卡片。
- 横屏高度不足时优先单行/双 pane，禁止高卡片导致首屏只露出很少内容。

### 6.2 媒体比例

- 推荐应用 Banner：`16:9`。
- Feed 竖向卡片：`3:4` 或 `4:5`，但必须稳定，不随标题行数改变卡片高度。
- 详情页媒体预览：按素材真实比例展示，设置最大高度，避免超出首屏。
- 图片使用 `ContentScale.Crop` 时必须允许裁剪非关键信息；需要完整展示的素材使用 `Fit`。

### 6.3 卡片信息层

卡片内信息按优先级降级：

1. 标题：必须保留，`maxLines = 2`，最小 `12.sp`。
2. 作者：保留头像或名称之一；窄屏可只显示头像/短名称。
3. 核心统计：最多 1-2 个；低优先级统计在窄屏隐藏。
4. 标签：最多 2-3 个，使用 `FlowRow` 或横向省略；不能撑破卡片。

最低规范：

- 卡片标题 `lineHeight >= fontSize + 3.sp`。
- 统计图标和文字最小 `10.sp`，低于 `10.sp` 的信息视为不可读，应隐藏而不是继续缩小。
- 叠加渐变区高度不得超过卡片高度的 35%，避免覆盖核心封面。
- 文案必须 `maxLines` + `overflow = TextOverflow.Ellipsis`，同时保证同行图标不会被压到 0 宽。

## 7. 文本、控件和可访问性

### 7.1 字体

- 优先使用 `MaterialTheme.typography`，只有特殊视觉卡片可以局部指定 `sp`。
- 正文最小 `12.sp`，按钮/标签最小 `11.sp`，非关键角标最小 `10.sp`。
- 禁止通过屏幕宽度线性缩放所有字体。字体大小必须尊重系统字体缩放。
- 必须测试 `fontScale = 1.3`，核心流程还要测试 `fontScale = 1.5`。

### 7.2 触控区域

- 可点击控件最小触控区域 `48.dp`。
- 紧凑工具按钮视觉尺寸可以小于 `48.dp`，但外层 clickable 区域必须达到 `48.dp`。
- 主按钮高度不低于 `48.dp`；次按钮不低于 `40.dp`。
- 列表项、底部导航、图标按钮必须设置明确 `contentDescription` 或由文本提供语义。

### 7.3 可变内容

必须考虑：

- 中文长标题、英文长单词、数字过万、用户名为空或很长。
- 标签数量超出 3 个。
- 图片加载中、加载失败、视频封面缺失。
- 会员名、金额、任务状态等字段长度变化。
- 多语言和 RTL 后续扩展，布局不要依赖“右下角永远是唯一动作”。

## 8. iOS / iPad 特别规则

Compose Multiplatform 仍需要遵循 iOS 的 Safe Area、Dynamic Type 和 Size Class 思路：

- 不把内容贴到屏幕物理边缘，关键内容约束在 Safe Area 内。
- iPhone 刘海、灵动岛、Home Indicator 下，顶部/底部自定义区域必须留出安全区。
- iPad 不按设备名判断，按窗口宽度判断；Split View 可能让 iPad 退回 `Compact`。
- iPad 横屏和 `Expanded` 以上应提供双栏或最大宽度，不允许手机单栏无限拉宽。
- 需要完整展示的图片不得被强行拉伸；本地位图资源保留 `@2x` / `@3x` 或等价密度资源。
- 动态字体放大后，主要按钮、输入框、底部面板不得被裁切。

## 9. RunningHub 页面级规范

### 9.1 发现页 / 社区页 / 创作者作品

当前相关文件：

- `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/feature/discovery/DiscoveryScreen.kt`
- `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/feature/community/CommunityScreen.kt`
- `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/feature/creator/CreatorProfileScreen.kt`

规范：

- 网格使用 `GridCells.Adaptive` 或显式按窗口类计算列数。
- 双列卡片宽度不足 `160.dp` 时退回单列。
- 卡片统计区在 `CompactSmall` 下只保留一个核心指标。
- 顶部标签栏使用横向滚动或 `FlowRow`，禁止压缩文字到不可读。
- 首屏底部必须给底部导航留出安全距离，最后一行内容不能被导航遮挡。

### 9.2 快捷创作

当前相关文件：

- `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/feature/quickcreate/QuickCreateScreen.kt`
- `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/feature/quickcreate/TuneBottomSheet.kt`
- `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/feature/quickcreate/MediaChipCard.kt`

规范：

- 底部输入面板在竖屏最多占可用高度的 45%；横屏或 `HeightCompact` 下必须可滚动。
- 键盘弹出时使用 `imePadding()`，发送按钮必须保持可见。
- 调优面板在 `Compact` 下用底部面板，在 `Medium` 以上可切换为居中面板或侧面板。
- 媒体引用卡片过多时列表化，不允许把输入框挤出屏幕。
- 工具 chip 支持横向滚动，但单个 chip 文案必须省略，不能撑破父容器。

### 9.3 详情页

当前相关文件：

- `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/feature/detail/AppDetailScreen.kt`

规范：

- `Compact` 下单列滚动，底部主操作栏固定并处理安全区。
- `Medium` 以上可使用媒体预览 + 表单/参数双栏。
- 底部操作栏使用 `navigationBarsPadding()`，主按钮高度不低于 `48.dp`。
- 表单项长标题和长 placeholder 必须换行或省略，不能挤压输入控件。

### 9.4 个人中心

当前相关文件：

- `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/feature/profile/ProfileScreen.kt`

规范：

- 快捷入口不能固定 `80.dp * 4` 横排；`CompactSmall` 下改为 3 列或 `FlowRow`。
- 资产卡片在窄屏可上下堆叠，不能让金额文本互相挤压。
- 用户名、会员名、金额都必须设置 `maxLines` 和省略策略。
- `Medium` 以上可把资产、统计、设置分区做双列卡片。

### 9.5 搜索页

当前相关文件：

- `composeApp/src/commonMain/kotlin/com/runninghub/app/ui/feature/search/SearchScreen.kt`

规范：

- 搜索输入框全宽，但在 `Medium` 以上设置最大宽度并居中。
- 热门标签使用 `FlowRow`，标签过长时省略。
- 搜索结果在 `Medium` 以上可从单列列表升级为双列卡片或列表-详情结构。

## 10. 禁止清单

以下写法进入新代码前必须改掉，旧代码触碰时同步修：

- `GridCells.Fixed(2)` 用在 Feed/卡片流且没有最小卡片宽度判断。
- `contentWindowInsets = WindowInsets(0, 0, 0, 0)` 后页面内部没有安全区处理。
- `.height(fixed).navigationBarsPadding()` 导致底部栏内容被安全区压缩。
- 用固定 `width(80.dp)`、`height(200.dp)` 控制响应式卡片和网格项。
- 文本小于 `10.sp` 仍承担有效信息。
- 多个长文案放在同一 `Row`，没有 `weight`、`maxLines`、`overflow` 或优先级隐藏。
- 强制锁死竖屏来规避布局问题。
- 全局修改 density 或接入 AndroidAutoSize 作为默认适配策略。
- 忽略字体大小、显示大小、键盘、分屏、横屏。

## 11. 验收矩阵

每个涉及布局的 PR 至少覆盖以下矩阵。没有自动化条件时，PR 描述必须写明手动验证设备/模拟器和结论。

### Android

| 场景 | 逻辑尺寸目标 | 必测内容 |
| --- | --- | --- |
| 小屏手机 | `320 x 568dp` 左右 | 单列降级、底部导航、安全区、字体放大 |
| 主流手机 | `360 x 640dp` / `393 x 851dp` | 发现页双列、快捷创作输入、详情页底部按钮 |
| 大屏手机 | `411 x 891dp` / `430 x 932dp` | 卡片间距、首屏内容密度、底部栏 |
| 横屏手机 | 高度 `< 480dp` | 底部面板高度、键盘、横向滚动 |
| 折叠屏展开 | `600 - 839dp` 宽 | Medium 布局、双栏候选、网格列数 |
| 平板横屏 | `840dp+` 宽 | Expanded 布局、内容最大宽度、导航 Rail/侧栏 |
| 系统设置 | 字体 1.3/1.5，显示大小最大 | 文案不裁切、按钮不重叠、列表仍可滚动 |

### iOS

| 场景 | 逻辑尺寸目标 | 必测内容 |
| --- | --- | --- |
| iPhone SE | `320 x 568pt` | 单列降级、安全区、底部栏 |
| iPhone 标准 | `375 x 667pt` / `390 x 844pt` | Feed 双列阈值、卡片信息层 |
| iPhone Max | `430 x 932pt` | 大屏手机内容密度 |
| iPhone 横屏 | 高度 `< 480pt` | 输入面板、顶部/底部安全区 |
| iPad Split View | `320 - 600pt` 可变宽 | 从 Compact 到 Medium 的动态切换 |
| iPad 全屏 | `768pt+` / `1024pt+` | 双栏、最大宽度、侧栏 |
| Dynamic Type | 放大字号 | 文本不重叠、主按钮可点 |

### 通用验收标准

- 无文本重叠、按钮重叠、图标挤成 0 宽。
- 关键内容不被状态栏、刘海、灵动岛、导航栏、Home Indicator、键盘遮挡。
- 所有可点击目标实际触控区域不小于 `48.dp/pt`。
- 图片不变形；裁剪是设计选择，不是布局副作用。
- 列表首项、末项和加载更多不被顶部/底部栏挡住。
- 横竖屏、分屏、折叠展开后状态不丢失，布局可重新计算。
