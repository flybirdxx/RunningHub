# Chinese Commenting Governance

本文件承接 `AGENTS.md` 中的中文注释强制规范，作为后续协作者可独立读取和执行的细则。

## 基本原则

- 中文注释属于代码交付内容，不是可选项。
- 新增或修改生产 Kotlin 代码时，必须补充必要的简体中文 KDoc、块注释或行注释。
- 注释解释设计意图、业务规则、数据流、边界条件、并发约束和异常处理，不复述语法。
- 类名、函数名、参数名、协议名和通用技术术语可以保留英文。
- 修改已有逻辑时，必须同步检查并更新相关注释。
- 与实现不一致的注释视为缺陷；不得为了减少工作量删除仍有效的注释。

## 必须使用 KDoc 的声明

以下新增或修改的 Kotlin 声明必须使用 `/** ... */` 中文 KDoc：

- public、internal 的类、接口、枚举和 sealed class/interface。
- Repository、UseCase、Interactor、Coordinator、ScreenModel。
- public、internal 的函数和扩展函数。
- 具有业务语义的数据模型和值对象。
- `expect` / `actual` 平台抽象。
- 非显而易见的配置对象和常量。

KDoc 根据实际情况说明：

1. 类型或函数承担什么职责。
2. 为什么需要它，以及它位于哪一层。
3. 参数含义、单位、格式和有效范围。
4. 返回值以及可能出现的状态。
5. 副作用，例如网络请求、数据库写入、文件操作或状态更新。
6. 并发、协程、线程和生命周期约束。
7. 可能发生的业务错误及调用方处理方式。
8. Android 与 iOS 的平台差异。

## 字段级注释

以下类型只写类级概述不算完成，必须逐字段说明：

- `UiState`、页面状态和应用状态。
- Domain model、值对象和业务配置。
- DTO、Entity、Request、Response。
- 导航参数、事件、Action、Intent。
- 计费、任务、分页、上传、媒体和认证相关模型。

字段注释可以使用类级 KDoc 的 `@property`，也可以写在属性声明前。不要对同一个属性重复说明。

字段注释至少覆盖代码类型无法表达的信息：

- 业务含义：该值在当前业务流程中代表什么。
- 数据来源：用户输入、服务端返回、本地缓存、计算结果或派生状态。
- 格式约束：长度、编码、正则、ID 类型、URL 类型或枚举取值。
- 单位与范围：毫秒、秒、字节、百分比、页码、金额、数量等。
- 默认值语义：`""`、`0`、`false`、空集合分别代表什么。
- 空值语义：`null` 与空字符串、空集合或默认对象的区别。
- 生命周期：何时赋值、清空、失效，是否跨页面或跨进程保存。
- 状态关系：与其他字段之间必须满足的约束或不变量。
- 安全属性：是否属于密码、Token、Cookie、API Key 或其他敏感数据。

不同类型的最低要求：

- `Boolean`：明确写出 `true` 和 `false` 各自代表的业务状态。
- `String`：说明内容格式、是否允许空字符串，以及空字符串的业务含义。
- ID 字段：说明它标识的实体、来源以及是否稳定可持久化。
- 数值字段：说明单位、有效范围以及 `0`、负数等特殊值的语义。
- 可空字段：说明 `null` 的具体业务含义。
- 集合字段：说明元素类型、顺序是否有意义、是否允许重复以及空集合含义。
- 时间字段：说明时间单位、时区和序列化格式。
- 金额字段：说明币种、精度、结算口径以及是否允许负数。
- URI、URL、文件字段：说明本地或远程、有效期、权限和可访问范围。
- 加载状态：说明对应哪一个请求或流程。
- 错误状态：说明何时设置、谁负责展示、何时清空以及是否可重试。

## 复杂逻辑注释

下列逻辑必须在代码附近添加中文块注释或行注释，重点解释“为什么”：

- 多阶段业务流程。
- 复杂条件和状态转换。
- 分页、刷新、去重和缓存策略。
- 协程并发、Job 取消、Mutex 和防抖。
- Token 刷新、401 重试和会话失效。
- 任务提交、轮询、超时、取消和失败恢复。
- 计费预览、余额判断和价格计算。
- DTO、Entity 与 Domain Model 映射。
- 兼容旧接口或异常服务端数据的处理。
- 安全相关处理和敏感数据脱敏。
- Android/iOS 平台行为差异。
- 临时规避方案以及无法立即消除的技术债务。

复杂函数应按执行阶段解释业务意图，例如：

```kotlin
// 第一阶段：校验用户输入，避免无效参数进入计费和任务提交链路。

// 第二阶段：取消旧的价格预览请求，防止旧响应覆盖用户刚刚修改的新参数。

// 第三阶段：只有价格预览通过后才允许提交任务，避免余额不足时仍产生远程任务。
```

## 禁止的注释方式

禁止添加没有维护价值的注释：

```kotlin
// 设置 loading 为 true
state.loading = true

// 调用接口
api.loadData()
```

应解释代码本身无法表达的信息：

```kotlin
// 在请求发出前立即进入加载状态，避免用户连续点击导致同一页被重复提交。
state.loading = true

// 此处必须复用 Repository 的分页入口，确保搜索结果与首页列表采用相同的错误映射规则。
repository.loadPage()
```

## TODO 和临时方案

`TODO`、`FIXME` 和临时兼容逻辑必须包含：

- 产生原因。
- 当前风险。
- 后续移除条件。
- 相关任务编号；没有任务编号时写明待办内容。

生产 Kotlin 源码中的 `TODO` 和 `FIXME` 必须使用可追踪格式，例如 `TODO(RH-124)`。
`checkLongTermGovernance` 会拦截没有任务编号的生产源码 TODO/FIXME；治理文档中的示例不参与该检查。

示例：

```kotlin
// TODO(RH-124): 服务端暂时会返回空的 skuId。
// 当前使用 bindingId 作为降级标识；服务端完成数据修复后应删除此兼容分支。
```

不得使用以下无信息量写法：

```kotlin
// TODO: later
// FIXME
// 临时处理
```

## 修改完成检查

提交结果前逐项确认：

- [ ] 新增和修改的核心类型具有中文 KDoc。
- [ ] UiState、Domain model、DTO、Entity、Request、Response 的每个属性均有字段级中文说明。
- [ ] Boolean 已解释 `true`/`false`；可空字段已解释 `null`；数值已注明单位和范围。
- [ ] public、internal 函数具有必要的中文 KDoc。
- [ ] 复杂流程已经按阶段添加中文注释。
- [ ] 并发、状态转换和异常降级策略已有说明。
- [ ] 注释解释的是原因和约束，而不是复述语法。
- [ ] 没有过时、错误或与实现冲突的注释。
- [ ] 没有泄露 Token、Cookie、API Key、密码等敏感信息。
- [ ] 最终回复中说明本次新增或更新了哪些注释。
